# wx-admin PBX login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `wx-admin login [--pbx] <host>` signs in to a PBX with a Company API Key or a login and password (Basic first,
else the WMS token sign-in with 2FA, the password always kept); the x-bees login leaves `wx-admin`; `status` tells
where commands go and how.

**Architecture:** `wldx-core` gets a CLI mode without x-bees profiles, a single-choice picker and an echoed prompt.
`wx-admin` gets `src/wms-login.mjs` (the `/api/v1/auth/*` protocol, no state) and a `password` access in `src/pbx.mjs`
(modes `basic` and `token`, moving between them, a retry on 401 in `pbxClient`). New commands `login`, `logout`,
`status` replace the core ones; `pbx add`/`pbx remove` become the same commands.

**Tech Stack:** Node ≥ 22 ESM, no dependencies, `node:test`, Biome 2.6.6 (120 columns), pnpm workspace.

**Spec:** `docs/specs/2026-11-07-pbx-login-design.md`

## Global Constraints

- Code, comments, identifiers, commit messages: English only; no attribution lines in commits.
- No dependency is added. Node ≥ 22 (`Response`, `Headers.getSetCookie()`, `fetch`).
- The password, the 2FA code, tokens, refresh tokens and `PHPSESSID` are never printed, logged, put in an error
  message, on a command line or in a child's environment. Access files: 0600 in a 0700 folder, written atomically.
- One sign-in attempt of each kind per command (Basic once, the token sign-in once): failed attempts may count
  towards the PBX's lockout. Basic is re-tried only at `login`, `status --check` and when a refresh is refused.
- `/api/v1/auth/*` requests carry no `Authorization` header and keep the trailing slash; the refresh token goes in the
  body as `refresh_token`; `redirect: 'manual'` (a 3xx is a refusal).
- Nothing from the internal WMS sources (paths, ticket, commit, SSH procedures, root password) in the repository.
- `wx` keeps its x-bees login unchanged; the core default (`profiles` not `false`) behaves exactly as today.
- Every task ends with `pnpm run check` green (lint + all tests + pack). The version stays 1.3.0 until the release
  is asked for (1.4.0, `node tools/version.mjs 1.4.0`).

## Review Focus

1. Lockout: a wrong password is tried at most twice per command (Basic + token sign-in), never in a loop, never on
   every request. (Task 4: attempt counters in the fake PBX.)
2. A Basic 401 alone never decides "wrong password": that comes from the token sign-in's 401. (Task 6.)
3. Two commands renewing at once: a newer refresh token or mode saved by another process is not lost. (Task 4.)
4. Piped password and a PBX that asks for 2FA, no `--code`: a usage error naming `--code`, no hang. (Task 6.)
5. No secret in any output: one test runs every flow and scans stdout, stderr, the log of `config import` and error
   messages for the password, code and tokens. (Task 6.)

**Interfaces:**
- Consumes: Task 3 `signIn`, `renew`, `signOut`, `WmsAuthError`, `fakeWms`.
- Produces:
  - `AUTH_TYPES = ['apikey', 'token', 'password']`; `savedAccess()` turns a legacy `{auth: 'basic', username,
    password}` into `{auth: 'password', mode: 'basic', …}` (on read; the file is rewritten on the next save).
  - `pbxBase(ctx, {host, port}) → string` (the address `pbxClient` uses, `WILDIX_PBX_URL` rule included).
  - `probeBasic({base, username, password, fetch}) → Promise<boolean>`: one `GET /api/v1/Dictionaries` with Basic;
    200 → true, 401 → false, anything else → `PbxError`.
  - `passwordAccess(ctx, access, {interactive}) → {header(): Promise<string>, onUnauthorized(): Promise<boolean>}`:
    mode `basic` → Basic header; on 401 → `signIn` with the saved password (2FA: `askCode` on a TTY via
    `readSecret`, else `AuthError` "…asks for a 2FA code: wx-admin login <host>"), mode `token` saved, `true`.
    Mode `token` → the saved access token while > 60 s left, else `renew`; renew `expired` → `probeBasic` once →
    mode `basic`, else `signIn` as above. Every change re-reads the file first and saves atomically (spec section 3,
    "Two commands at once"). `credentials` from `signIn` → `AuthError` "The password of <user> on <host> has
    changed: wx-admin login <host>".
  - `pbxClient`: a 401 with `target.onUnauthorized` → call it once; `true` → the request is sent again once.
  - `PbxError` 403 → `exitCode = 2`; the 403 hint for `password`: "this user needs the Admin role and the ACL of the
    menu".
